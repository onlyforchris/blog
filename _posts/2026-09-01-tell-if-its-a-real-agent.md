有个项目里做了个"生成式 AI 策略"。名字听着挺唬人，但说白了就是：**接一个接口，给一段提示词，出一个结果。** 它既不看结果优不优，也不基于结果再走下一步。

这不是个例。现在太多号称"AI"的东西，其实就是"调了一次大模型"。而真 agent 和不叫 agent 的区别，就卡在这一点上。这篇我想把这条判断线说清楚。

## 先定义：agent 是个循环，不是一次调用

我理解的 agent，是**感知 → 决策 → 行动**，然后**循环**：拿到结果，看它对不对，再决定下一步，再行动……直到把目标达成。网上常说的"agent loop"（像 Anthropic 那套）跑的就是这个。

- **感知**：拿到当前状态，比如一个任务、一堆数据、一次报错。
- **决策**：基于这个状态，判断该怎么走。
- **行动**：真正去做——调一个工具、写一个文件、发一个请求、改一个状态。
- **循环**：看行动的结果，回到决策，继续走，直到达成目标。

关键在**"循环"**这两个字。如果只有一次"感知→决策→输出"，那它只是个**能用自然语言回答问题的生成器**，不是 agent。

## 一次调用缺了什么

一次"接口 + 提示词"能给你一个答案，但它没有三样东西：

1. **没有反馈**：它不认识自己刚才的输出对不对，只能靠你人眼看。
2. **没有纠错**：万一它第一步就错了，它不会自己发现、自己重来。
3. **没有行动**：它只吐出文字，不真正推动任何事情发生。

这三样恰恰是 agent 最值钱的地方。**agent 能做多步、会纠错、能在真实世界里推动事情**，所以它才配被信任去做那些"一步错就麻烦"的事。

## 怎么判断一个 AI 功能是不是真 agent

看它是不是 agent，别听它叫什么，问几个具体的问题：

**1. 它只是输出，还是真的动手？**
如果它给你的是一段文字、一个建议，那它是**文本生成器**。只有它真的去**调工具、发请求、改状态、产生副作用**，才谈得上"agent"。这是最硬的一条——agent 得"做"，不能只"说"。

**2. 它会基于结果再决策一次吗？**
如果一个调用完就结束了，那它没有循环。真 agent 会看结果，再决定下一步：这一步没成，换个办法；这步成了，继续下一步。

**3. 它会把一个大目标拆成几步来走吗？**
"帮我筛选并联系这批候选人"这种目标，真 agent 会拆成：解析简历 → 画像匹配 → 判断符合度 →（符合的）发消息要更多信息 → 记录结果。它心里清楚"现在到哪一步了、还剩几步"。

**4. 它出错了怎么办？**
这是最见功底的地方。一次调用出错了，往往就抛个错或答个"我做不到"就完了。真 agent 会**重试、换策略、降级**，或者**停下来找人确认**，而不是硬着头皮往下走。

**5. 它有记忆吗？**
下一步能不能做对，往往取决于它记不记得上一步。真 agent 要把"做过什么、做到哪、还差什么"带进下一步，不然每一步都是失忆重来。

## 为什么这条线这么重要

因为**会不会踩到坑**，就看你能不能分辨。

- 一个"只会调一次模型"的东西，你**不能**把多步、会副作用、不可逆的事交给它——它不会纠错，错了就错了，你还可能不知道。
- 一个真 agent，你**敢**交给它更重的事，因为它会自我纠正、能停下来、每一步都有迹可循、能被你确认。

很多项目失败，不是模型不行，是**把"调了模型"当成了"做完了业务闭环"**。到要真正交付时才发现：它只会答，不会做；一步错，满盘皆输。

## 但也别矫枉过正

不是每个场景都非得是 agent。**如果一件事就一步、没副作用、错了也无所谓，那一次调用就是最优解**，你非要上个循环反而是过度设计。

我要说的不是"人人都得上 agent"，而是：**你得能分辨这两者**。否则你会干两件很糟的事——要么把"一次调用"吹成"我们的智能体"，要么该用 agent 用力的地方，却没看出来它其实是个玩具。

## 一句话判断

站在一个 AI 功能面前，就问一句：**它会不会看着上一次的结果，自己决定下一步怎么走？** 会，再看它有没有真的在推进事情、会不会纠错、能不能停下来。这几条都占了，它才配叫 agent；只占一个"能回答"，那它就是个**好用的文本接口**。

把这条线拎清楚，你至少不会在汇报里，把一个"调了次模型"的东西，喊成"我们做了个智能体"。
